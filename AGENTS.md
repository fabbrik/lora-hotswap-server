# AGENTS.md

Guidance for AI coding agents working in this repo.

**What this is:** an ASP.NET host that keeps one llama.cpp base model resident and serves
per-tenant LoRA adapters by hot-swapping them per request, with fail-closed admission and
proof of which adapter served each answer.

**Map**
- `src/LoraHotswap.Core.Ports` -- interfaces; `Core` -- domain; `Infrastructure` -- LLamaSharp runtime, GGUF/safetensors readers; `Api` -- HTTP host (`/v1/generate`)
- `tools/acquire` (download pinned model+adapters), `tools/convert` (PEFT -> GGUF), `tools/compare` (binding strategies), `tools/capture` (regenerates README "What this does" + `docs/three-tenants.md`)
- `tests/LoraHotswap.Tests` -- xunit.v3; asset-dependent tests skip with a reason
- `GOTCHAS.md` -- traps found while building; read before changing runtime or merge code

**Commands:** `dotnet build LoraHotswap.slnx -c Release && dotnet test LoraHotswap.slnx -c Release --no-build`.

**Invariants:** dependency direction is enforced by a test; never serve an adapter that failed admission; never hand-edit the block between `BEGIN/END GENERATED by tools/capture`; `models/`, `adapters/`, `tools/convert/vendor/` are gitignored.

**Done:** per-tenant API keys + admin key (`EndpointSecurity`), `/healthz`, Prometheus `/metrics` (`ServingMetrics`), Dockerfile (linux/amd64).

**Good next steps:** a second runtime behind the existing port (e.g. vLLM-style batched LoRA); adapter eviction/LRU under memory pressure and loading adapters without a restart; an OpenAI-compatible route; arm64 container support (needs a TorchSharp-free merge check); rate limits per tenant; other base models via config and tests.
